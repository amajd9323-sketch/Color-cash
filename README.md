# Color Clash

مشروع ألعاب ويب عربي بتصميم Dark Neon، مهيأ للهاتف والكمبيوتر. تتوفر حالياً لعبة Color Clash، وأُضيفت قاعدة مشتركة لتجهيز غرف Multiplayer للألعاب XO ونبات جماد حيوان وركلات الترجيح.

## الميزات

- 10 جولات في كل مباراة.
- 3 تحديات: اكتشاف اللون المختلف، مطابقة اللون، والذاكرة.
- توقيت 20 ثانية لكل جولة.
- تسجيل أفضل نتيجة فردية على الجهاز.
- إنشاء غرفة خاصة برمز من 6 أحرف والانضمام إليها.
- مزامنة اللاعبين والجولات والنقاط لحظياً عبر Supabase.
- تسجيل دخول مجهول إلى Supabase؛ لا يحتاج اللاعب إلى إنشاء حساب.
- PWA قابلة للتثبيت مع Service Worker ودعم تخزين الملفات الأساسية للاستخدام الفردي دون اتصال.\n- بنية قاعدة بيانات مشتركة لغرف XO ونبات جماد حيوان وركلات الترجيح عبر Supabase Realtime.

## تشغيل اللعبة

يمكن فتح `index.html` مباشرة للعب الفردي، أو نشر المستودع على GitHub Pages.

## تفعيل اللعب الجماعي (مرة واحدة)

1. أنشئ مشروعاً في Supabase.
2. من **Authentication → Sign In / Providers** فعّل **Anonymous Sign-Ins**.
3. افتح **SQL Editor** في مشروعك، والصق محتوى `supabase.sql` ثم شغّله.
4. بيانات مشروع Color Clash الافتراضية مضمنة في التطبيق، ويحاول الاتصال تلقائياً عند فتحه. يمكن تغييرها من **الإعدادات** عند الحاجة.
5. أنشئ غرفة وشارك الرمز مع اللاعب الثاني. على الجهاز الثاني افتح رابط اللعبة ثم انضم باستخدام الرمز.

**تنبيه مهم:** بموافقة صاحب المشروع، ملف `supabase.sql` يحذف ويعيد إنشاء جداول Color Clash القديمة الثلاثة (`cc_room_submissions` و`cc_room_answers` و`cc_rooms`)؛ ستُفقد غرف ونتائج Color Clash السابقة. جداول الألعاب المشتركة الجديدة (`game_rooms` و`game_room_events`) تُنشأ دون حذف بياناتها الموجودة. شغّل الملف مرة واحدة من SQL Editor. لا تستخدم `service_role` key داخل المتصفح. لا تستخدم `service_role` key داخل المتصفح. صلاحيات القراءة مقيدة بأعضاء الغرفة، وتغييرات حالة الغرفة والنقاط تتم من خلال RPC functions. هذا مناسب كنموذج لعب أولي، لكنه ليس نظاماً تنافسياً محصناً ضد الغش على مستوى البطولات؛ يلزم إضافة حدود إنشاء الغرف، انتهاء صلاحية الغرف، ومراقبة إساءة الاستخدام قبل إطلاق تجاري واسع.

## النشر عبر GitHub Pages

أُضيف workflow في `.github/workflows/pages.yml` للنشر التلقائي عند كل تحديث لفرع `main`.

لأول مرة:
1. افتح **Settings → Pages** في المستودع.
2. اختر **GitHub Actions** كمصدر النشر، إذا لم يكن محدداً.
3. افتح تبويب **Actions** وتأكد من نجاح مهمة **Deploy Color Clash to GitHub Pages**.
4. سيكون رابط الموقع عادة: `https://amajd9323-sketch.github.io/Color-cash/`.

## تثبيت اللعبة على Android

بعد نشر الموقع افتحه في Chrome على الهاتف، ثم اختر **Install app / Add to Home screen** من قائمة المتصفح. هذا يثبت نسخة PWA. للحصول على APK مستقل عبر Capacitor يلزم بناء Android باستخدام Node.js وAndroid Studio على جهاز كمبيوتر.

## الملفات

- `index.html`: واجهة اللعبة ومنطق اللعب والاتصال بـ Supabase.
- `manifest.json`: بيانات تطبيق الويب.
- `icon.svg`: أيقونة التطبيق.
- `sw.js`: التخزين المؤقت للأصول الأساسية.
- `supabase.sql`: جداول Color Clash والجداول المشتركة للألعاب الثلاث الأخرى، وسياسات RLS ودوال RPC.\n\n> ملاحظة التطوير: قاعدة البيانات المشتركة أصبحت جاهزة كبنية أولية، لكن واجهات XO ونبات جماد حيوان وركلات الترجيح وربطها بهذه الدوال لم تُدمج بعد في `index.html`.
- `.github/workflows/pages.yml`: النشر الآلي إلى GitHub Pages.


## بناء APK للأندرويد عبر GitHub Actions

أُضيف إعداد Capacitor ومسار بناء آلي لنسخة Android:

1. افتح تبويب **Actions** في المستودع.
2. اختر **Build Android APK**.
3. اضغط **Run workflow** وانتظر انتهاء المهمة بنجاح.
4. افتح نتيجة التشغيل ثم نزّل Artifact باسم **Color-Clash-debug-APK**.
5. فك ضغط الملف وستجد `app-debug.apk` لتثبيته على هاتف Android.

يُعاد بناء APK تلقائياً عند تحديث ملفات التطبيق الأساسية. هذه نسخة Debug للتجربة والتثبيت اليدوي؛ إصدار Google Play الموقّع يحتاج إعداد مفتاح توقيع خاص بشكل آمن.
